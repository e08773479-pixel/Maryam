# MEKA — ميكا

منصة تواصل ومراسلة بواجهة عربية RTL، وهوية بصرية مستقلة، مع إمكانية التوسع لإضافة المحادثات والمجموعات والحالات والمكالمات.

## 1. ملفات المشروع

- `index.html` — هيكل واجهة التطبيق.
- `styles.css` — التنسيقات والتصميم المتجاوب.
- `manifest.json` — إعدادات تثبيت التطبيق.
- `logo.svg` — الشعار الأساسي.
- `app.js` — تسجيل الدخول والملفات الشخصية والمحادثات.
- `service-worker.js` — التخزين المؤقت لملفات الواجهة.
- `README.md` — دليل المشروع.
- `icon.svg` — أيقونة التطبيق.

## 2. قاعدة البيانات

المشروع يستخدم قاعدة Supabase الموجودة مسبقًا.

لا تنشئ مشروع قاعدة بيانات جديدًا، ولا تحذف الجداول أو السياسات الموجودة.

الجداول المستخدمة تشمل:

- profiles
- conversations
- conversation_members
- messages
- message_attachments
- calls
- call_participants
- user_settings
- notifications
- stories
- communities
- community_members
- posts
- post_media

قد تختلف الأعمدة والقيود والسياسات الفعلية عن افتراضات كود الواجهة؛ لذلك يجب اختبار كل عملية قبل الاعتماد عليها.

## 3. إعداد Supabase

يجب التأكد من إعداد:

1. Authentication.
2. Google OAuth عند الرغبة في تسجيل الدخول بجوجل.
3. سياسات Row Level Security (RLS).
4. سياسات التخزين للصور والملفات.
5. Realtime للجداول التي تحتاج تحديثًا مباشرًا.

لا تعطل RLS لتجاوز أخطاء الصلاحيات.

لا تضع مفتاح `service_role` داخل ملفات الواجهة.

المفتاح المستخدم في الواجهة يجب أن يكون Publishable Key فقط، مع ضبط الصلاحيات والسياسات المناسبة.

## 4. تسجيل الدخول بجوجل

من إعدادات مشروع Supabase:

1. افتح Authentication.
2. افتح Sign In / Providers.
3. فعّل Google.
4. أدخل بيانات OAuth المطلوبة من Google Cloud.
5. أضف عنوان موقعك إلى قائمة Redirect URLs المسموح بها.
6. اختبر تسجيل الدخول والعودة إلى التطبيق.

يجب استخدام عنوان الاستضافة الحقيقي، وليس عنوانًا افتراضيًا.

## 5. التشغيل

يمكن نشر المشروع على استضافة HTTPS مثل GitHub Pages.

تأكد من وجود الملفات في المسارات الصحيحة، وأن أسماء الملفات في HTML تطابق أسماء الملفات الموجودة فعليًا.

بعد النشر:

1. افتح الموقع.
2. اختبر تحميل الواجهة.
3. اختبر تسجيل الدخول.
4. اختبر إنشاء الملف الشخصي.
5. اختبر البحث عن مستخدم.
6. اختبر إنشاء محادثة وإرسال رسالة.
7. راقب Console وطلبات الشبكة عند ظهور أي خطأ.

## 6. ملاحظات مهمة

- لا تعتبر وجود زر في الواجهة دليلًا على اكتمال الوظيفة.
- المكالمات الحقيقية تحتاج WebRTC وإعدادات signaling وأذونات الأجهزة.
- الإشعارات الفورية تحتاج إعدادًا مناسبًا.
- رفع الملفات يحتاج سياسات تخزين صحيحة.
- العمل على نطاق ملايين المستخدمين يحتاج اختبار تحميل ومراقبة وأمانًا وتوسعة للبنية الخلفية.
- يجب اختبار التطبيق على الهاتف والكمبيوتر قبل إطلاقه.
